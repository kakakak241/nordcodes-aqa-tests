# Дефекты и наблюдения

## NC-001. Отклоняются токены с допустимыми буквами G–Z

В задании разрешены 32 символа из A–Z и цифр. Приложение отклоняет токены `G` × 32, `Z` × 32 и `ABCDEFGHIJKLMNOPQRSTUVWXYZ012345`.

Для воспроизведения внешний `/auth` должен возвращать HTTP 200. В приложение передаётся запрос с правильным API-ключом и телом:

```text
action=LOGIN&token=GGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGG
```

Ожидается успешный вход и вызов `/auth` с этим токеном. Фактически приложение возвращает HTTP 400 / ERROR, внешний сервис не вызывается. В сообщении об ошибке указано ограничение `^[0-9A-F]{32}$`.

Автотест: `TokenValidationIT.acceptsTokensFromRequiredAlphabet`. Из семи вариантов токена не проходят три, перечисленные выше.

## Наблюдения за пределами описанного контракта

- На HTTP 301 без `Location` от внешнего `/auth` приложение возвращает OK и разрешает ACTION. В задании не определено, какие внешние коды считать успешными.
- GET `/endpoint` и POST с `Content-Type: application/json` возвращают HTTP 500 / ERROR. В задании предусмотрен только POST с form-urlencoded; ожидаемый ответ на другие форматы не указан.
